## Cross-Model Consistency Result

### Stable thesis direction
All three runtimes converge on the same core causal map:

`Global AI Capex → optical bandwidth upgrade → shipment/mix → revenue/margin → working capital/capex → FCF/ROIC`

All three also converge on the same thesis direction:

- Demand / Revenue / Margin: **STRENGTHENS**
- Working capital / cash conversion: **constraint / watch**
- Policy / CPO-NPO architecture: **material uncertainty**
- Stock valuation: cannot be inferred directly from industrial leadership

No runtime reverses the thesis without introducing new evidence. This is the first positive Cross-Model Consistency signal for v0.4.

## Runtime personality drift

- **WorkBuddy**: most aggressive in market narrative, consensus-based forward valuation and investment wording.
- **Grok Bot**: most conservative; strongest on evidence labels, unknowns, scope and date discipline.
- **Grok Chat**: middle ground; retains strong evidence discipline while adding more valuation and policy framing.

This style drift is acceptable if the causal chain, evidence states and thesis direction remain stable.

## Shared weakness — likely Skill-level, not runtime-level

All three runtimes underdevelop **Reverse Expectations**. They mostly ask whether forward consensus makes PE look cheap/expensive, but do not fully invert the current market cap into required sustainable mid-cycle earnings / FCF / ROIC.

### Recommended v0.4 addition
For public equities where market value is available, STANDARD should include a light Reverse Expectations module when valuation is material:

1. Current Market Cap / EV
2. Select appropriate normalized valuation anchor(s) — explicitly labeled as assumption/scenario
3. Back-solve sustainable earnings / FCF / NOPAT required by current price
4. Translate required economics into operating variables (shipment, ASP/mix, margin, working capital, capex, share)
5. Build `Peak / Mid-cycle / Down-cycle` cases
6. Compare implied capital returns with WACC where data permits

The purpose is not to generate a target price; it is to expose what the current price requires the business to deliver.

## v0.4 status

One case now has three-runtime evidence of directional consistency. This is not enough to release v0.4. Repeat the same cross-runtime test on the remaining fixed cases before changing the Skill core.
